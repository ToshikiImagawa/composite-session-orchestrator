# HTML 画面の、実ブラウザでの確認（T23）

CI にはブラウザを入れない（依存になるため）。画面を変えたら、手元で次を実行して確かめる。Playwright は依存に加えず、環境にあるものを使う。

```sh
pnpm build
CSO_PLAYWRIGHT=$(npm root -g)/playwright CSO_OUT=/tmp/ui node scripts/ui-browser-check.mjs
```

`CSO_CHROMIUM` で実行ファイルを変えられる（既定 `/opt/pw-browsers/chromium`）。スクリプトは、daemon の窓口を、種になる状態（子の報告・判断要求に、スクリプトタグと `onerror` の文字列を入れる）で立てて、明・暗の両方で開く。

## 確かめること（PR1・PR2。2026-10-23 に確認）

| 項目 | 期待 | 結果 |
| --- | --- | --- |
| `/ui#token=…` で開く | 読み込み後、アドレスにトークンが残らない | 残らない（`/ui` に置き換わる） |
| 子が書いた文字列に `<img onerror>`・`<script>` | 実行されず、文字として表示される。`window.__xss` が立たない | 文字として表示。立たない |
| コンソールのエラー・ダイアログ | なし（CSP に違反しない） | なし |
| 貼り付けの入力欄 | トークンなしで開くと出る。誤ったトークンで「正しくありません」。正しいトークンで接続 | そのとおり |
| SSE で接続 | 表示が「SSE」 | 「接続中（SSE・seq N）」 |
| 状態の変化の反映（SSE） | 2 秒以内（NFR_008） | 約 0.2 秒 |
| SSE が使えない（429） | 「ポーリング」に切り替わり、ETag で 200 のあと 304 | そのとおり（200・304・304・304） |
| 429（Retry-After 5 秒） | その秒数より前には、SSE に再接続しない | 4 秒の間に、接続の要求は 1 回 |
| 通知が続いても、取り直しは最短 1 秒ごと | 3 秒の間に 30 回変えても、状態の取得は 3〜4 回 | 3 回 |
| SSE が切れる（1 回目の接続を中断） | 指数バックオフで再接続し、「SSE」に戻る | 約 1.3〜1.5 秒で再接続（接続の要求は 2 回） |
| ETag・304 | 変化がない間は 304（本文なし。描き直さない）、変わった直後は 200（新しい ETag） | 200 のあと 304。変更後は 200 |
| 人間以外のトークン（403） | 「人間のトークンが必要です」（401 の「正しくありません」と分ける） | そのとおり |
| `constructor` という名前のノード | 木に出る（表の引き当てを間違えない） | 出る |
| 明・暗の配色 | どちらも読める | 読める（`prefers-color-scheme`） |

## 操作（PR3。2026-10-23 に確認）

daemon の窓口の実物に、記録するだけの仮のハンドラ（`decision.answer`）を付けて確かめる（`out.operations`）。

| 項目 | 期待 | 結果 |
| --- | --- | --- |
| 選択肢で回答 | 押しても、すぐには送らない。確認に、質問と回答が出る。「戻る」で閉じる | そのとおり |
| 二重クリック | 「この内容で送る」を二重クリックしても、要求は 1 回 | 1 回 |
| 自由入力 | 空・制御文字は、確認に進まず、理由が出る。複数行は、確認に全文が出る | そのとおり |
| 入力中の再描画 | 状態が更新されても、入力中の文が残る | 残る |
| 失敗 | `code: cause` が出て、確認に戻る。同じ内容で再送でき、**同じ requestId** | そのとおり（UUID） |
| 長い質問・長い選択肢 | 質問は 2,000 文字まで読め、超えたら「…（省略）」。長い選択肢のボタンは無効で、自由入力を促す。確認にも長い質問が出る | そのとおり |
| 429（Retry-After 2 秒） | 「あと N 秒待つ」で、送れない。時間が来たら、押せるようになり、送れる | そのとおり |
| XSS（質問・選択肢） | 確認画面でも、実行されない | 実行されない |
| 拡張要求の承認（T23-b） | 対象（`src/ok.ts`）が、カードと確認に出る。送るのは `extensionId`・`decision` だけで、1 回 | そのとおり |
| 最終削除（T23-d） | 事前確認の内容（ノード数・墓標・保管の数）が確認に出る。根の ID を打ち込むまで送れない（前後の空白・大文字・全角は不一致）。一致すれば送れ、送る params は `nodeId` だけ | そのとおり |
| 実行できない木 | 理由が出て、打ち込みの欄もなく、送れない | そのとおり |
| 保留（30 日） | 打ち込みなしの確認。期限は ISO 8601 UTC で、約 30 日後 | そのとおり |
| 保留の日数（T23-d2） | 範囲外（400 など）は、理由が出て確認に進まない。45 日は、確認に期限が出て、その期限で送る。365 日は、10 分短い期限で送る | そのとおり |
| 保管の一覧・削除 | 読み込むまで出ない。件名の制御文字は除かれる。key を打ち込むまで削除できず、`expectTip` が一覧の先端で送られる。削除後は読み込み直される | そのとおり |
| 隠れた対象（`../outside/secret`） | 値は画面のどこにも出ない。承認・切り出しは無効で、却下だけ押せる | そのとおり |
| 回収の指示のボタン（T23-c） | 停止したノードで、指示済みでないものだけ。指示済みには「破棄を指示済み」。実行中のノードには出ない | そのとおり |
| 回収の指示の確認 | 取り消せない旨・満たしていない条件・原因（プロセスの pid）・失われるもの（コミット数・未保存・未追跡）・先端（12 桁）が出る。件名の XSS 文字列は、文字として出て、実行されない。確認の前に、指示の要求は出ない | そのとおり |
| 打ち込み（対象のノード ID） | 一致するまで送れない（`S1`・前後の空白・全角・一部は不一致）。無効化を迂回しても、要求が出ない | そのとおり |
| 先端の照合 | 見せたあとで先端が変わると、送っても `tipMismatch` で、確かめ直しの案内（同じ内容の再送は案内しない）。送った `expectTips` は、見せた先端 | そのとおり |
| 確かめ直し | 戻る→もう一度で、新しい先端が出て、通る。`requestId` は新しい。二重クリックでも 1 回。通ったあと、行が「破棄を指示済み」になる | そのとおり |
| 失われるものを調べられない | 理由と cli の案内が出て、打ち込みの欄がなく、送れない | そのとおり |
