# 回収（破棄）の前に、失われるものを確かめる（T21r）

停止したノードの成果を捨てる回収（`cso reclaim`）は、取り返しがつかない。作業ツリーとブランチを、強制して消す（`git worktree remove --force`・`git branch -D`）。
そのため、破棄を指示する前に、**何が失われるか**を表示し、人間が `--yes` を付けたときだけ、破棄の判断を記録する。

## 使い方

```
cso reclaim <nodeId>          # 失われるものを表示して止まる（終了コード 2）
cso reclaim <nodeId> --yes --expect <digest>    # 表示した照合の値を付けて、破棄を指示する（node.reclaimInstruct）
```

`--yes` は**必須**（以前は、確認なしで、すぐに指示していた。破壊的な変更）。失われるものがない場合も、破棄の判断なので、`--yes` を要求する。
指示のあと、統合ノードの回収（`node.reclaim`）が、記録を見て、強制して消す（T10r2）。

## 表示される内容

対象と配下のノードのうち、作業ツリーがあって、失われるものがあるノードごとに:

- **統合されていないコミット**の数と、その件名（新しい順に 5 件まで。1 件 100 文字まで）。数は、上流（親のブランチ）との差。上流が分からなければ「数が不明」。
- **追跡中のファイルの、未保存の変更**があるか。
- **未追跡のファイル**の数。再生成できる gitignore の対象（`node_modules`・`dist`・`.turbo` など、daemon の設定 `regenerableIgnored`）は、数えない。それ以外の gitignore の対象（`.env` など）は、数える。

失われるものがなければ「失われるもの: なし」。daemon が情報を返せなければ（古い daemon）、「情報が得られない」と出す。

## 件名は、信頼できない入力

件名は、コミットメッセージ由来の**信頼できない文字列**。

- daemon が、空白を詰めて 1 行にし、制御文字（エスケープ列を含む）を除き、長さを切って返す（`sanitizeText`）。結果のフィールド名は `untrustedSubjects`。
- 人間のロールにだけ返る。統合ノード（エージェント）の呼び出しでは、`loss` を計算せず、結果にも含めない（git の負荷を避ける）。指示として扱わない。
- cli は、端末へ出す直前に、もう一度、制御文字・双方向の制御文字を除く。

## daemon の操作（`node.reclaimPreview`）

- 結果に、任意の `loss`（`NodeLoss` の配列）が付く。空配列は「失われるものなし」、省略は「情報なし」（`lossFor` がない）。
- **人間のロールも呼べる**（読み取りだけ。部分木の制限なし。存在しないノードは `notFound`）。統合ノードは、これまでどおり、自分の部分木の下だけ。
- 何も変えない（記録しない）。
- **調べられなかったものは「なし」にしない**。`lossFor` が失敗・例外のノードは、`unknown: true` で `loss` に残す（cli は「調べられなかったノードがある：<nodeId>。失われるものが分からない」と出す）。`git status` だけが失敗したノードは、`workingTreeUnknown: true`（`uncommitted`・`untracked` は不明）。
- 作業ツリーは消えたがブランチだけ残ったノードは、ブランチ側の上流との差と件名を返す（`factsFor` の同じ状態の扱いと同じ）。

## 限界

- 入れ子の `node_modules` は、先頭のディレクトリ名だけで判定するので、多めに数える（安全側。数が実際より多く出ることはあっても、少なく出ることはない）。
- 表示は**スナップショット**だが、表示した先端と照合する（T21r-e。下の節）。件名・数が古くなる、ブランチにコミットが足される、は、検出して拒否する。
  実際に消えたブランチの先端は、`reclaimForced`（記録）と、ノードの `lastCommit` で追える（T13f-c）。保管（T13f-r）にも残る。
- 件名・数は、`git` の表示を使う。巨大なリポジトリでは、取得に時間がかかりうる（1 ノードずつ、順に取る）。

## 表示した先端と照合する（T21r-e）

表示から `--yes` の指示、指示から実際の回収までの間に、ブランチにコミットが足されると、**見ていない成果が消えてしまう**。これを防ぐ。

- **プレビュー**（`node.reclaimPreview`。人間にだけ）の結果に、`tips`（ノード ID → ブランチの先端の SHA）が付く。対象と配下の、作業ツリーを持ち、先端を取れたノードだけ（取得に失敗したノードは載せない）。
- **cli** は、先端の先頭 12 桁と、全体の**照合の値**（ID 順の `id:SHA` の SHA-256 の先頭 12 桁）を表示し、`cso reclaim <id> --yes --expect <値>` を案内する。**`--yes` には `--expect` が要る**。指示の時点で取り直したプレビューの値が `--expect` と違えば、何も指示せずに終了コード 1（新しい値を案内する）。これで、「人間が表示を見た」から「`--yes`」までの間の変化も防ぐ。先端の数が 256 件（`expectTips` の上限）を超えるときは、はっきり失敗する。
- **指示**（`node.reclaimInstruct`）は、**`expectTips` が必須**（空でもよい。cli は、取り直したプレビューの `tips` を渡す）。
  - 対象は、表示した先端と今の先端が（どちらもなし、を含めて）一致しなければ、**何も記録せず** `tipMismatch`。表示になかった先端が、今は取れる、も不一致。この照合は、記録済み（冪等）の分岐より**前**に行う。
  - 先端の取得に失敗したノード（ブランチがないのとは別）は、「なし」と取り違えず、**不明として `tipUnknown`** で拒否する（指示・回収の両方）。
  - 配下は、表示した先端のうち、強制になりうる（停止した）ノードだけを照合する。表示に出ていない配下の先端は照合しない（検証済みで、統合済みのノードは `-d` で消え、先端が動いても無害）。
  - `expectTips` のキーは、対象と配下だけ（外は `invalidRequest`）。値は、小文字の 16 進で 40 桁か 64 桁。件数は 256 まで（`LIMITS.expectTips`）。
  - 記録するのは、対象だけ（配下の停止ノードは、別の指示）。**必ず、`expectTip`（確かめた先端）か `noTip: true`（先端がなかった）のどちらかを `node.discardDecided` に残す**（再起動をまたいでも照合できる。fail-closed）。
  - **指示し直し**: 回収が `tipMismatch` で止まったあと、見直した先端で指示し直すと、記録の先端を**更新**する（回収可能にした済みのノードにも許す。デッドロックしない）。同じ内容の再送は、何も変えない。
- **回収**（`node.reclaim`）は、強制になるノード（記録上、破棄を判断した停止ノード）の先端を、記録と照合する。`expectTip` があれば一致、`noTip` なら、いま先端が取れれば不一致、取得失敗は `tipUnknown`。①最初の削除の**前に、全ノードをまとめて**（1 つでも違えば、何も消さない）、②各ノードの `-D` の**直前**に、もう一度。違えば `tipMismatch`（作業ツリーもブランチも、保管も、そのまま）。
- `expectTip` も `noTip` もない判断（この機能の前の記録）だけが、回収では照合しない（これまでどおり）。
- **二重の保護**: 強制の `-D` の直前に、ポートが先端を `refs/cso/discarded/` に保管する（T13f-r）。照合をすり抜けて消えた成果も、保管から取り戻せる。
- **`tipMismatch`・`tipUnknown` の原因・次の操作・監査のログに、SHA は出さない**（ノード ID だけ）。もう一度 `cso reclaim` で、失われるものを確かめ直す。
- 保存データの版（`STATE_VERSION`）は 11（`node.discardDecided` に `expectTip`・`noTip`）。

## 画面から（T23-c）

HTML 画面（`docs/ui.md`「回収の指示」）からも、同じ破棄の指示ができる。cli と同じく、プレビューで内容を見せ、**見せた先端（`tips`）を `expectTips` としてそのまま送る**（違えば、何も記録せず `tipMismatch`）。画面は、さらに、**対象のノード ID を打ち込ませる**。失われるものを調べられなかったノードがあるとき（`unknown`・`workingTreeUnknown`）は、画面からは指示できない（cli で確かめる）。
