# 自動の最終削除（`autoPurge`）

daemon の設定ファイルの `autoPurge` で、保持期間を過ぎた木を自動的に最終削除できる。**既定はオフ**（省略するとオフ）。

## 有効にすると何が起こるか

**保持期間（`retentionDays`。既定 90 日）を過ぎた、アーカイブ済みの最上位の木が、取り返しのつかない形で消える。**
木のノードに関するイベントの行（本文を含む）が、ログのファイルから物理的に削除される（`secure_delete`・`wal_checkpoint`）。
バックアップ・OS のコピーには残りうる。墓標（タイトル・結果・最終コミットの SHA・日付）は、`purgeTombstone`（既定は残す）に従って標識に残る。
破棄した成果は、最終削除までは `refs/cso/discarded/*` に保管されている（`docs/discarded-work.md`。最終削除で、その木のノードの保管も消える）。保管が消えたあと、最終コミットの SHA は、成果の保管ではなく、取り戻すための手がかりにすぎない（git が掃除するまでの間だけ、`git branch <名前> <SHA>` で戻せることがある）。

人間のコマンド（`cso purge`）と同じ関数・同じ検査を通る（最上位の木・木全体がアーカイブ済み・木の外から依存されていない・保持期間・
残りのログを畳み込めること）。違いは、操作の主体が `system` で、監査の記録に `origin: "auto"` が付くことだけ。

## 設定

```json
{
  "retentionDays": 90,
  "purgeTombstone": true,
  "autoPurge": { "enabled": true, "intervalMinutes": 60, "maxTreesPerRun": 2, "noticeDays": 7 }
}
```

| 項目 | 意味 | 既定 |
| --- | --- | --- |
| `enabled` | 自動の最終削除を有効にする（必須） | （`autoPurge` ごと省略するとオフ） |
| `intervalMinutes` | 実行の周期（分。1〜1440） | 60 |
| `noticeDays` | 予告（受信箱の項目）を出してから、削除するまでの日数（1〜30）。予告の後にだけ削除する | 7 |
| `maxTreesPerRun` | 1 回の実行で消す木の数の上限（1〜100）。アーカイブが古い順 | 2 |

- **有効にするときは、`retentionDays` を 7 以上にする**（0〜6 だと、設定の検査で起動に失敗する。省略した既定の 90 は可）。
  保持期間の短い自動の削除が、アーカイブの直後に記録を消すのを防ぐため。
- **根のノード（`parentId` が null）は、自動では消えない。** 根は、人間のコマンド（`cso purge`）でだけ消せる。
- **時計の異常への対策と、止まっていた時間:**
  - **daemon が止まっていた時間は、予告の期間に数えない。** 起動のとき、最初の周期の前に、イベントログの最後の記録（`at`。起動の整合が書く前のもの）と現在の差を調べ、
    1 日以上なら、有効な予告をすべて出し直す（古い予告は system が解決済みにして取り下げる。人間が解決済みにしていても、新しい予告が後ろにつくので、古いほうは判定に使われない）。
    出し直した予告から `noticeDays` 日たつまで、削除しない。
  - 実行の前に、壁時計の経過と単調時計（`process.hrtime`）の経過の差を、直前の確認と比べる。差が `min(noticeDays の半分, 1 日)` を超えたら、その回の実行を止め、
    理由を付けて `autoPurge.skipped` に記録する。**前に飛んだ**（壁時計だけが進んだ。時計の誤設定・停止からの復帰など）ときは、予告も出し直す
    （飛んだ時間も、予告の期間に数えない）。後ろに戻ったときは、止めるだけ。
  - 時計がイベントログの最後の記録より前に戻っているときも、その回を止める。
  - 動きのない daemon（長い間、記録を書かない）でも、自動の削除は止まらない（ログの最後の記録からの経過では止めない）。
- 木を 1 本処理するごとに、イベントループに譲る。ただし、削除そのもの（ログの行の物理削除）は同期で行うので、**大きなログでは、短い間、応答が遅くなる**。
- **予告（T13f-n）:** 削除の対象になった木ごとに、受信箱に `info` の項目を 1 件出す（持ち主は、木の根の親。木のノードに付けると、削除で一緒に消えるため）。
  要約に、削除の予定日・木の中の未回答の判断の数・未解決の項目の数を載せる。**削除は、予告が出てから `noticeDays` 日たったものだけ。**
  daemon が止まっていて、保持期間をだいぶ過ぎてから起動した場合も、予告を今出して、`noticeDays` 日後に削除する。予告は 1 回の実行で 20 件まで。1 本の木に 50 件の予告が出たら（出し直しが続いた場合）、`autoPurge.noticeFailed` に理由を書いて、その木の自動の削除を止める（人間のコマンドで消す）。
  - **止める方法（木ごとの保留。T13f-h）:** 人間が `cso purge-hold <nodeId> [--until <日時>] [--reason <理由>]` で、その木を自動の削除の対象から外す。
    `nodeId` は、**予告の `nodeId` と同じもの**＝自動の削除の対象になる木の根（アーカイブ済みで、親がアーカイブされていないノード。`parentId` が null のノードではない）。
    `--until`（ISO 8601 UTC。現在より後、365 日先まで）を省略すると無期限。保留中に別の期限で呼べば、置き換わる（延期・短縮）。`cso purge-release <nodeId>` で解除する。
    - 保留をかけると、**有効な予告は、その場で取り下げる**（system が解決済みにする。次の周期を待たない）。保留中は、予告も出さず、削除もしない。
    - **木の中のどのノードの保留でも、その木全体を自動の対象から外す。** 子 T に保留をかけたあとで、親 P がアーカイブされ、P を根とする新しい木に T が吸収されても、
      保留が有効なうちは、P の木も消さない（予告も出さない）。保留が切れる・解除されると、P の木に予告を出し、そこから `noticeDays` 日たつと消える。
      自動の削除の最後の関門（`purgeTreeOf`）にも、同じ判定がある（`purgeHeld`）。
    - 期限つきの保留は、期限が過ぎると対象に戻る。**予告は出し直し、そこから `noticeDays` 日待つ**（期限の直後に、予告なしで消えることはない）。解除したときも同じ。
    - 期限は、自動の削除と同じ時計（時計の異常の検知を通ったもの）で判定する。時計が飛んだ回は、実行そのものが止まる。時刻を読めないときは、保留のままにする（迷ったら保留）。
    - **人間の `cso purge` は、保留を無視して消せる**（保留は自動の削除だけを止める）。対象の表示に「保留中」を出し、無視して消したときは、監査に `purge.purgeHoldIgnored` を残し、
      標識（`node.purged`。永続する記録）にも `holdIgnored: true`（期限があれば `holdUntil`）を残す。墓標を残さないときも、標識に残る。
    - 保留は、木のノードを主語とするイベント（`node.purgeHeld`・`node.purgeHoldReleased`）として記録され、最終削除で、木の行と一緒に消える（墓標には残らない）。監査は `purge.held`・`purge.released`。
    - 人間のロールだけの操作（`node.purgeHold`・`node.purgeRelease`）。mcp には公開しない。
    - ほかに、`autoPurge` を無効にするか、`retentionDays` を延ばして daemon を再起動する方法も使える。
    削除の直前に保持期間をもう一度判定するので、予告のあとで `retentionDays` を延ばせば、予告済みでも消えない。その予告は、system が解決済みにして取り下げる
    （また対象になれば、予告を出し直し、そこから `noticeDays` 日待つ）。
  - 木が対象から外れたとき（保持期間を延ばした、親がアーカイブされて最上位でなくなった、外から依存された、など）も、予告を system が解決済みにする。
  - **人間が予告を解決済みにしても、削除の条件は変わらない。** 判定に使うのは、予告の項目が出たことと、その時刻（`at`）。解決済みにしても、早くは消えず、`noticeDays` 日たてば消える。
  - 削除のあとも、予告を system が解決済みにする（受信箱に残り続けない）。
- 最初の実行は、daemon の起動から 1 周期後（起動直後は消さない）。
- 1 回の実行が前の実行と重ならない（実行中なら次は飛ばす）。1 本が失敗しても、記録（`autoPurge.failed`。同じ木・同じ原因は 1 日に 1 回まで）に残して次の木へ進み、次の周期で再試行する。
- ログの整合が壊れた（`fatal`）後は動かさない。daemon の停止（`stop`）では、実行中の 1 回が、木ごとに停止を確かめて残りを処理せず、終わるのを待ってから、ストアを閉じる。
- 記録の名前: `autoPurge.noticePosted`・`autoPurge.noticesReissued`・`autoPurge.noticeWithdrawn`・`autoPurge.noticeFailed`・`autoPurge.noticeResolveFailed`・`autoPurge.purged`・`autoPurge.failed`・`autoPurge.skipped`・`autoPurge.error`、監査は `purge.purgeStarting`・`purge.purged`・`purge.purgeFailed`（`origin: "auto"`）。
